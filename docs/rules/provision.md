# Снабжение и сбор войск

Go хранит состояние и проверяет все команды. React показывает реальные допустимые
варианты и новые армии; рендер 3D-поля не изменён. UI поддерживает RU/EN, клавиатуру,
сенсорные кнопки, закрытие и повторное открытие окна через «Снабжение и войска».

## Снабжение

`Room.BeginSupply(catalog, now)` — внутренний эффект события Вестероса, не публичная
команда ведущего. Снабжение **не** пересчитывается после каждого похода.
Дома обрабатываются по Железному трону: подсчитываются реально контролируемые бочки
(максимум 6), при превышении лимитов дом выбирает отряды для расформирования.
Два и более корабля в море/порту тоже образуют армию, одиночные фигуры — нет.

```json
{"type":"disband","revision":42,"region":"winterfell","units":{"footman":1}}
```

Удаление требует подтверждения в UI. Сервер проверяет фазу, текущий дом, владение
отрядами и количество. Расформирование выполняется по области; можно сделать
несколько действий, пока армия не станет допустимой. Затем автоматически
переходит следующий дом или управление возвращается резолверу Вестероса.

Установленные жетоны контроля учитываются отдельно от обычного занятия области
(`Match.controlTokens`). Удаление последней фигуры не создаёт новый жетон. Уже
установленный жетон сохраняет контроль; без него пустая родная область возвращается
своему дому, обычная становится свободной. Корабли в потерянном порту удаляются.
Доступная власть ограничена общим пулом 20 за вычетом установленных жетонов.
Старые снимки, созданные до учёта `controlTokens`, не содержат надёжной информации
о происхождении прежнего контроля; для точной проверки правил лучше начать новую партию.

## Сбор войск

`Room.BeginMustering(catalog, now)` — внутренний эффект события Вестероса. Дома
набирают войска по Железному трону. Каждый контролируемый замок даёт одно очко,
крепость — два; очки разных областей не объединяются.

```json
{"type":"muster","revision":43,"region":"winterfell","target":"winterfell","unit":"knight","upgrade":true}
```

Стоимость сервер пересчитывает сам: пехота/корабль — 1; рыцарь/осадное орудие — 2;
улучшение пехоты до рыцаря/осадного орудия — 1. Пехота при улучшении возвращается
в запас. Запас вычисляется из лимитов каталога и фактических фигурок на поле.
Нельзя превысить снабжение, запас или очки области. Одно действие создаёт/улучшает
одну фигуру. DTO не принимает от клиента стоимость или новый баланс очков.

Сухопутные фигуры появляются в исходном замке. Корабли — в соседнем море без
вражеских кораблей либо в связанном порту. В порту максимум три корабля;
вражеский флот в связанном море не запрещает набор в свой порт.
Захват и замена чужих кораблей при завоевании порта остаются отдельным будущим правилом.

```json
{"type":"finish_muster","revision":44}
```

Завершение теряет все оставшиеся очки текущего дома. UI требует отдельного
подтверждения. При отсутствии допустимых действий дом заканчивает автоматически.
Все проверенные варианты находятся в `View.mustering.options`; интерфейс не
выдумывает назначения, стоимость и доступность набора.

## Особый сбор власти — работает в обычной партии

После набегов и походов обычные приказы сбора власти разрешаются автоматически
по очереди домов. Звёздный приказ в замке/крепости приостанавливает завершение
раунда и предлагает выбор:

```json
{"type":"consolidate","revision":45,"region":"winterfell","choice":"muster"}
```

`choice` — `power` или `muster`. Первый вариант получает обычную власть с учётом
оставшегося пула. Второй тратит очки **только** этой области и не получает власть.
При завершении локального набора обрабатываются следующие приказы, затем начинается
новый раунд. Звёздный сбор вне замка/крепости выдаёт обычную власть автоматически.
Портовый сбор власти пока не включён: полные портовые правила — отдельный этап.

## Сохранение и автоматизация

Приватный снимок комнаты сохраняет очередь домов и оставшиеся очки. Персональные
HTTP/WS-проекции содержат только публичные армии, запас, лимиты и допустимые варианты.
Сервер проверяет ревизию и членство; чужие или повторные устаревшие команды отклоняются.
Боты исполняют по одному решению за tick. Мягкий таймер ничего не решает; жёсткий
удаляет лишние фигуры текущего дома, завершает набор без дополнительного расхода
очков либо выбирает власть для особого приказа. Следующее решение получает новый срок.

## Проверка

```bash
go test -race -count=1 ./...
cd web && pnpm test && pnpm build && cd ..
node scripts/sync-web.mjs
WESTEROS_BROWSER_TEST=1 go test -count=1 -run '^Test(Influence|Provision)Browser$' -v ./internal/server
```

Браузерные тесты используют настоящий Go HTTP/WS и временную SQLite, без fixture API
в production, без изменения volume с партиями и без подмен результатов команд.
Эффекты Supply/Mustering пока запускаются только тестовым движком: в обычной партии
их начнёт вызывать будущий резолвер трёх колод Вестероса.
