# Тайные ставки и влияние

Статус: серверный движок и интерфейс RU/EN подключены к обычной партии.
Со второго раунда торги запускаются соответствующим событием Вестероса,
а не автоматически каждый раунд независимо от карт.

## Интерфейс

Окно открывается для всех домов при начале трека и при переходе к ничьим.
Его можно закрыть (в том числе Escape) и снова открыть кнопкой «Открыть торги»
в нижней панели. Подтверждённая ставка остаётся на сервере. Неподтверждённый
черновик локальный и при перезагрузке не сохраняется.

Ввод проверяет целое число и текущую доступную власть, включая явный ноль.
Первое нажатие только показывает предупреждение; отправка происходит после
второго подтверждения. Ошибка, например конфликт ревизии, показывается внутри
окна; актуальный снимок запрашивается повторно, ставку можно отправить ещё раз.

Видны готовность домов и собственная ставка. После раскрытия показываются все
суммы, распределённые места и кнопки выбора только для действующего распорядителя
ничьих. Следующий трек сбрасывает локальный черновик. По окончании отчёт трёх
треков доступен через «Итоги влияния», в том числе после reload; очередь событий продолжается.
Окно поддерживает RU/EN, Tab/Shift+Tab, возврат фокуса и кнопки не меньше 44px.

## Запуск и завершение

Резолвер карты «Битва королей» вызывает `Room.BeginClashOfKings(now)` в фазе
`westeros`. Это внутренний Go hook, а не команда ведущего или публичный endpoint.
Он проверяет треки до изменения состояния и последовательно открывает торги за
`ironThrone`, `fiefdoms`, `kingsCourt`.

После третьего трека управление возвращается в `westeros`; серверная очередь C.2
на следующем automation tick продолжает оставшиеся события по сохранённому курсору.
Обычный переход между раундами входит в `BeginWesteros`; торги начинаются,
только если раскрыта «Битва королей» или выбраны через «Чёрные крылья, чёрные слова».

## Приватное состояние

`Room.Influence` сохраняется в SQLite вместе с участниками, подтверждёнными ставками,
порядком уже распределённых мест, текущей группой равных ставок, предыдущими
результатами и владельцем права разрешать ничьи. Дедлайн находится в `Room.Clock`.
Нельзя отдавать `Room` или `SealedBids` напрямую по HTTP/WS.

До общей готовности баланс власти публично не меняется. Иначе разница баланса
раскрывала бы секретную ставку. Остальные команды получения/расходования власти
в этой фазе недоступны. Последняя ставка вызывает одновременное раскрытие и
списание всех сумм ровно один раз; потраченная власть не возвращается проигравшим.

## Команды существующего API

Все команды проходят обычную проверку членства и ревизии комнаты.
Дом берётся из места авторизованного участника, не из поля `house` команды.

```json
{"type":"bid","revision":42,"bid":0}
```

Ставка — целое число от нуля до доступной власти. `bid` обязателен: отсутствие
поля или `null` не означает согласие на нулевую ставку. Подтверждённую ставку
нельзя изменить, в том числе после переподключения.

```json
{"type":"influence_tie","revision":43,"target":"stark"}
```

Текущий распорядитель выбирает **следующий** дом только из `influence.tied`.
Сначала распределяется группа с наибольшей ставкой. Единственный оставшийся дом
в группе получает место автоматически; затем обрабатывается следующая группа.
Нулевая ставка не исключает дом из трека.

Во время торгов за сам Железный трон все ничьи разрешает его прежний владелец,
даже если первое место уже назначено другому дому. Трек меняется только после
полного распределения мест. В следующих торгах распорядителем станет новый владелец.
Жетон Меча при смене владельца не обновляет своё использованное состояние.

## Персональный снимок

`View.influence` содержит `track`, `stage` (`bidding` / `ties`), `tieBreakHouse`,
`ranking`, `tied`, `results` и безопасную проекцию `bids`:

- `submitted`: готовность каждого дома без суммы;
- `yourBid`: только собственная подтверждённая ставка; до выбора поле отсутствует;
- `values`: ставки всех домов, но только после общего раскрытия.

Предыдущие результаты текущих торгов доступны в `results`. После окончания всех
трёх треков они сохраняются в публичном `Match.lastInfluence`. Текущий `influence`
удаляется. Последовательность скрытых решений не добавляется в публичный журнал.

## Автоматизация

Планировщик находит `influence_bidding` и `influence_ties` в SQLite и сохраняет
ровно одно решение бота за tick. Ставки ботов используют только публичный остаток
власти, номер трека и сложность, не читают чужие скрытые суммы. При равенстве бот
предпочитает себя; это пока простая эвристика, не полноценная дипломатическая AI.

Мягкий таймер ничего не решает. Жёсткий таймер подтверждает ноль только за тех,
кто не ответил. На ничьей выбирает первый дом из показанной группы. Это fallback
таймера, а не правило обычного разрешения ничьих. Новое решение/трек получает
новый дедлайн, старое истечение не должно затронуть следующую фазу.

## Проверки

- Go unit: ноль, границы, повтор, приватность, полное списание, порядок треков,
  группы ничьих, старый/новый владелец трона, состояние Меча и локализация.
- SQLite: закрытие/повторное открытие БД с незавершённой ставкой и прежним дедлайном.
- HTTP/WS: собственная ставка, отсутствие чужой суммы, подмена дома, reconnect,
  конфликт ревизии и безопасное оповещение другого клиента.
- Серверная автоматизация: все три трека с нулевой властью без браузеров;
  таймер не перезаписывает уже подтверждённую ставку.
- 4 браузерных E2E на реальном Go HTTP/WS и SQLite: подтверждение/приватность/reload
  и RU/EN; полные три трека с передачей трона; планшет и нулевая власть;
  реальный конфликт ревизии и повтор без дублирования ставки.

### Запуск браузерной проверки

```bash
cd web
pnpm build
cd ..
node scripts/sync-web.mjs
WESTEROS_BROWSER_TEST=1 go test -count=1 -run '^TestInfluenceBrowser$' -v ./internal/server
```

Go-тест создаёт временную SQLite, подготавливает события через настоящий движок,
поднимает локальный тестовый сервер и запускает Playwright. Нет подмен HTTP-ответов
игры, модификаций Docker volume или fixture API в production. Обычный Playwright
прогон без этого Go-теста пропускает четыре сценария, которым нужны такие события.
Локально нужен установленный Chrome либо `CHROME_EXECUTABLE_PATH`
(см. `web/playwright.config.ts`). GitHub Actions устанавливает Chromium через
Playwright и запускает эти четыре сценария отдельным шагом с
`PLAYWRIGHT_MANAGED_CHROMIUM=1`; локальный запуск остаётся на системном Chrome.

Следующие шаги отмечаются в [PLAN.md](../../PLAN.md). Полные правила:
[второе издание](https://images-cdn.fantasyflightgames.com/ffg_content/agot-bg-2nd-ed/support/VA65_AGoT2_Rulebook_web.pdf).
