# Одичалые: серверные срезы D.1 / D.2

## Статус

Готовы девятикарточная закрытая колода, тайные взносы, общий исход защиты,
ничьи, сохранение и разрешение **всех девяти** карт в обоих исходах:
`silence-at-the-wall`, `skinchanger-scout`, `rattleshirts-raiders`,
`a-king-beyond-the-wall`, `massing-on-the-milkwater`, `crow-killers`, `mammoth-riders`,
`the-horde-descends` и `preemptive-raid`. Семь последних используют сохраняемые решения D.2.

Неизвестная карта или повреждённая граница не считаются завершённым эффектом
и не пропускаются таймером. React-интерфейс событий подключён, как и автоматическая
фаза Вестероса со второго раунда обычной партии.

Источники: [правила FFG](https://images-cdn.fantasyflightgames.com/filer_public/30/4f/304f72e3-4fe4-4f91-bfbe-75133161b092/va65_agot2_rulebook_web.pdf),
стр. 4, 22–23, [FAQ 2.0](https://images-cdn.fantasyflightgames.com/filer_public/cf/06/cf06eb26-48e3-46b9-b57c-f053beb2518d/agotbg_faq_v2_forweb.pdf),
и справочник девяти карт в локальных reference-материалах. Runtime от этих файлов
не зависит, Node-сервера и отдельного хранилища не добавлено.

## Вход из Вестероса

Существующая очередь C.2 создаёт `westeros.run.attack` по шкале 12 или карте
`wildlings-attack`. Следующий automation tick вызывает внутренний
`beginWildlingAttack`, проверяющий границу и состав колоды. Публичной команды
запуска, завершения или пропуска нападения нет.

Используются последовательные фазы:

1. `wildling_bidding`: все участники подтверждают взнос, включая нулевой.
2. `wildling_ties`: при необходимости владелец Железного трона выбирает один дом.
3. `wildling_effects`: карта открыта; разрешаются награда или штраф.
4. `westeros`: после **реально выполненного** эффекта очередь C.2 продолжает тот
   же курсор, без нового раунда и повторного раскрытия событий.

Если сумма взносов не меньше силы нападения, побеждает Дозор. Тогда важен
единственный высший вкладчик. При поражении важен единственный низший. При равных
значениях нужный дом выбирает владелец Железного трона, а не сервер случайным
образом. При силе 0 взносы и ничьи всё равно проходят; победа гарантирована.

## Закрытые взносы

`Room.Wildlings.Attack.Bids` использует общий `SealedBids`. Суммы хранятся только
в приватном снимке. Взнос не может быть отрицательным, превышать доступную власть,
отсутствовать или подтверждаться повторно. До общей готовности баланс власти
**не меняется**, иначе наблюдатель смог бы вычислить чужой взнос.

Последнее подтверждение раскрывает все суммы, списывает их ровно один раз,
считает общий результат и открывает решение ничьей либо карту. Карта не открывается
ни во время взносов, ни до выбора дома при ничьей. Незавершённые суммы, случайный
порядок, выбранный дом и дедлайн переживают повторное открытие SQLite.

Команды существующего API:

```json
{"type":"wildling_bid","revision":42,"bid":0}
```

```json
{"type":"wildling_tie","revision":43,"target":"stark"}
```

```json
{"type":"wildling_choice","revision":44,"choice":"fiefdoms"}
```

Последняя команда отвечает на `attack.choice`: `house`, `kind: influence-track`
и `options`. При награде доступны `ironThrone`, `fiefdoms`, `kingsCourt`, при
штрафе остальным домам — только два последних трека. Штраф снабжения использует
существующие `SupplyView` и команду `disband`, а не новый отдельный API.

Для Milkwater тот же контракт возвращает `kind: discard-card` и допустимые ID
карт дома. Например:

```json
{"type":"wildling_choice","revision":45,"choice":"roose-bolton"}
```

Для Crow Killers `kind` принимает значения `upgrade-footman`,
`destroy-knight` или `downgrade-knight`. В `options` приходят ID доступных
областей, `count` показывает оставшееся число улучшений/потерь/замен текущего
шага. Одна команда обрабатывает одну фигурку:

```json
{"type":"wildling_choice","revision":46,"choice":"winterfell"}
```

При награде `finish` позволяет отказаться от оставшихся улучшений. При штрафе
этот вариант запрещён. Внутренняя квота и очередь не попадают в публичный снимок.

Mammoth Riders использует `retrieve-card` с ID карты либо `finish` для награды;
при потерях — `destroy-unit`. В `unitOptions` передаются записи
`{id, region, unit, count}`: UI не должен разбирать составной ID самостоятельно.
Например, `choice: "winterfell:footman"` удаляет одну фигурку выбранного типа,
а не всю армию. ID повторно разрешается сервером по текущим своим отрядам.

Участник определяется по месту авторизованного игрока. Поле `house` в запросе не
позволяет внести власть за другого или присвоить право Железного трона. Работает
общая проверка ревизии: старый запрос получает конфликт и не меняет снимок.

## Колода и проекция

При старте партии сервер перемешивает девять уникальных экземпляров через
`crypto/rand` и сохраняет порядок в приватном `Room.Wildlings.Deck`:

- `silence-at-the-wall`;
- `preemptive-raid`;
- `crow-killers`;
- `rattleshirts-raiders`;
- `massing-on-the-milkwater`;
- `a-king-beyond-the-wall`;
- `mammoth-riders`;
- `the-horde-descends`;
- `skinchanger-scout`.

Карта берётся сверху после определения ключевого вкладчика. Пока эффект не
выполнен, она находится в `Attack.Card`, а в колоде остаётся восемь экземпляров.
После завершения она возвращается вниз без перемешивания. Проверяется физический
состав: повреждённая колода не должна начать нападение или повторить эффект.

`View.wildlings` содержит только:

- `remaining`: количество карт в закрытой части;
- `attack`: сила, готовность домов, свой взнос; после раскрытия — общие суммы,
  исход, нужная группа ничьих и затем открытая карта;
- `attack.effectsImplemented`: после раскрытия показывает, реализован ли этот
  эффект; до раскрытия всегда `false`, независимо от тайной карты;
- `attack.choice`: текущее публичное решение по треку; без внутренней очереди
  обработчика и без будущего порядка карт;
- `attack.excludedHouse`: дом, освобождённый только от повторного нападения
  «Передового отряда»; отсутствует в `bids.submitted` и не может внести взнос;
- `last`: публичный отчёт последнего **завершённого** нападения.

Будущий порядок и чужие ещё не раскрытые суммы не попадают ни в HTTP/WS, ни в
журнал. Проекции копируют карты/суммы/срезы, не ссылаясь на приватное состояние.
Право Ворона использует отдельную персональную проекцию `View.raven`, а не открытие
общей колоды.

## Реализованные последствия

`silence-at-the-wall` не меняет ресурсы после базового списания взносов.
Для `skinchanger-scout` при победе выбранному высшему вкладчику возвращается
его взнос. При поражении выбранный низший теряет оставшуюся доступную власть,
затем остальные в порядке хода теряют до двух доступных жетонов. Установленный
контроль с поля не забирается, отрицательной власти и превышения пула нет.

### Rattleshirt’s Raiders: снабжение

При победе выбранный высший вкладчик поднимает снабжение на 1, максимум до 6.
При поражении выбранный низший сначала опускает снабжение на 2, минимум до 0,
и при необходимости расформировывает армии. После него остальные дома в порядке
Железного трона опускаются на 1 и приводят армии в соответствие со шкалой.

Это изменение **трека**, а не пересчёт значков на карте. Вложенный
`SupplyResolution.source: wildlings` сохраняет текущий уровень и возвращается
в `wildling_effects`, не продолжая события Вестероса преждевременно. Очередь
эффекта продвигается **до** входа в расформирование: повторное открытие БД не
применяет снижение ещё раз. Обычное событие Supply по-прежнему пересчитывает
значки контролируемых областей.

### A King Beyond the Wall: влияние

При победе высший вкладчик выбирает один из трёх треков и перемещается на первое
место. При поражении низший сначала перемещается на последнее место всех трёх
треков. Затем каждый другой дом в порядке хода выбирает Вотчины или Королевский
двор и перемещается на последнее место выбранного трека. Относительный порядок
остальных домов сохраняется.

Право жетона определяется первым местом трека. Передача Валирийского меча
**не сбрасывает** `BladeUsed`: использованный жетон остаётся использованным.
`Match.RavenUsed` также сохраняется при перемещении домов по Королевскому двору;
он обновляется только на границе нового раунда. См. [Посыльный ворон](raven.md).
Нельзя выбрать трек за другого участника, выбрать Железный трон при штрафе
остальных домов или повторно изменить уже подтверждённое решение.

### Massing on the Milkwater: карты дома

При победе высший вкладчик возвращает весь свой сброс в руку. Руки остальных
домов не меняются. При поражении низший вкладчик, если у него изначально более
одной карты в руке, сбрасывает **все** карты с наибольшей силой. Затем остальные
в порядке хода, если у них больше одной карты, выбирают и сбрасывают по одной.
Дома с единственной картой на начало своего штрафа освобождены от него.

Состав штрафа низшего фиксируется один раз в приватном
`effect.remainingCards`. Каждое подтверждение удаляет одну цель из этого списка,
а не заново ищет наибольшую силу в изменившейся руке. Очередь и список переживают
закрытие SQLite, включая промежуток между двумя сбросами.

По [FAQ 2.0, стр. 4](https://images-cdn.fantasyflightgames.com/filer_public/cf/06/cf06eb26-48e3-46b9-b57c-f053beb2518d/agotbg_faq_v2_forweb.pdf),
если у низшего остались две карты одинаковой силы, он выбирает первую для сброса,
затем сбрасывает последнюю: последняя остаётся в сбросе, остальные шесть
возвращаются в руку. Поэтому условие «более одной» проверяется **до** начала
штрафа, а не после каждого сброса. Возвращённые карты не становятся новыми целями.
Используется общий `discardCard`, без отдельного варианта восстановления руки.
В проекцию попадает текущий выбор, но не внутренняя очередь/список целей.

После выполненных последствий угроза становится 0 при победе Дозора или
уменьшается на два деления / 4 силы при поражении, не ниже 0. Карта возвращается
в колоду и сохраняется публичный результат. Повторный тик не применяет штраф
ещё раз. Нападение по шкале и более позднее по карте могут пройти в одной фазе.

### Crow Killers: замены фигур и потери

При победе высший вкладчик может заменить до двух своих пехотинцев в любых
сухопутных областях доступными рыцарями. Можно отказаться сразу или после одного
улучшения. Квота ограничена наличием пехоты на поле и рыцарей в физическом запасе.
Это замена 1:1, а не набор: очки замков и доступность снабжения не расходуются.

При поражении низший сначала заменяет всех своих рыцарей доступной пехотой;
остальные в порядке хода заменяют по два (или всех, если их меньше двух).
Если фигур пехоты не хватает, игрок сначала выбирает, какие рыцари будут
уничтожены, затем — какие из оставшихся будут заменены. Обязательную часть
нельзя закончить досрочно. Дома без рыцарей пропускаются.

`effect.units` хранит исходную квоту и число необходимых уничтожений. Счётчики
уменьшаются после каждой команды и не пересчитываются по изменившейся армии
при reload. После завершения дома очередь продвигается, не позволяя повторить
потери. Общий `reserve` ограничивает запас фигур, при гибели последнего отряда
используется существующее восстановление контроля и очистка приказа. Жетоны
установленного контроля не создаются и не забираются автоматически. Полные
правила портов остаются отдельным незавершённым пунктом плана.

### Mammoth Riders: потери и возврат карты

При победе высший может вернуть одну выбранную карту из собственного сброса,
либо отказаться; пустой сброс не создаёт награду. Рука остальных не меняется.
При поражении низший выбирает три отряда, остальные в порядке хода — по два;
если у дома меньше отрядов, он теряет только имеющиеся. Выбор включает все
четыре типа фигур, сухопутные, морские и портовые области. Нельзя отказаться
от обязательной части или выбирать чужие фигуры.

Квота хранится в `effect.units.remaining`; опустевшие области — в приватном
`effect.units.vacated`. После каждой команды выбор обновляется, следующий
дедлайн начинается отдельно. Контроль и зависимые порты очищаются после
всех выбранных потерь **этого дома**, чтобы гибель последнего сухопутного
отряда не убрала заранее корабли, которые игрок тоже хочет включить в квоту.
После завершения сохранённые жетоны контроля остаются; осиротевшие порты
очищаются существующим обработчиком. Полные правила захвата портов не входят
в этот срез. Перезапуск не отменяет уже выбранные потери и не повторяет награду.

### The Horde Descends: один замок и вложенный набор

При поражении низший вкладчик уничтожает два отряда **в одной** своей области
с замком/крепостью, если там есть хотя бы два отряда (FAQ 2.0, стр. 4). Если такой
области нет, выбирает до двух имеющихся отрядов где угодно; можно из разных
областей, включая корабли. Остальные дома теряют по одному отряду, в порядке хода.
Дома без фигур пропускаются. Обязательные потери нельзя закончить досрочно.

`effect.units.castleOnly` сохраняет исходное ограничение, а `region` — область
первой выбранной потери. После reload условие «хотя бы два» не пересчитывается:
оставшийся отряд всё равно должен быть уничтожен в том же замке. Используются
структурированные `unitOptions` и команда `wildling_choice` с `region:unit` ID,
как для Mammoth Riders. Очистка опустевших земель/портов выполняется после всех
потерь дома; правила портов не расширяются в этом срезе.

При победе высший вкладчик получает `kind: muster-region`: ID контролируемых
замков/крепостей и `finish` для отказа. Выбор сохраняется до входа во вложенный
набор. `Mustering.source: wildlings` и `region` фиксируют источник и единственную
область набора. Используются существующие `muster`, `finish_muster` и `MusterView`:
очки 1/2, физический запас фигур, снабжение, улучшения, морские области и порты
проверяются общим валидатором. Нельзя набрать войска во втором замке.

Неиспользованные очки можно не тратить; при отсутствии замков или легальных
вариантов эффект завершается без набора. После окончания возвращается
`wildling_effects` того же нападения, затем сохранённый курсор Вестероса —
не `consolidate_power` и не следующий раунд. Очки, область и очередь сохраняются
в SQLite, поэтому перезагрузка не позволяет повторить награду.

### Preemptive Raid: штраф или повторное нападение

При поражении только низший вкладчик выбирает `kind: preemptive-penalty`:
`destroy-units` (до двух имеющихся отрядов где угодно) либо `lose-influence`
(вниз на две позиции на своём высшем треке). Можно выбрать вариант, который
невозможно выполнить полностью: в частности, снижение влияния, даже если дом
последний на всех треках (FAQ 2.0, стр. 4). Остальные дома не получают штраф.

Для потерь используются общий `destroy-unit`, структурированные `unitOptions`,
сохраняемая квота и отложенная очистка портов. При снижении выбирается трек,
где дом ближе всего к первому месту. Если таких треков несколько, решение
`influence-track` принимает **текущий владелец Железного трона**, а не обязательно
низший вкладчик. Если все треки уже последние, бессмысленное решение пропускается.
Снижение ограничено последним местом, не отправляет на дно вместо двух позиций
и не восстанавливает использованный Валирийский меч при передаче жетона.

При победе карта завершается и возвращается вниз колоды, угроза становится 0.
В той же сохраняемой транзакции запускается новый `wildling_bidding` силой 6,
без продвижения курсора Вестероса или раунда. Прежний высший вкладчик исключён
из `Bids.Participants`: не платит, не может стать высшим/низшим и не получает
наград/штрафов следующей карты. Исключение действует только на это нападение.
Если исключённый дом владеет Троном, он по-прежнему разрешает ничьи.

У повторного нападения собственные пустые взносы, дедлайн и скрытая карта;
она раскрывается только после новых взносов и нужной ничьей. `last` содержит
уже публичный результат первого нападения — это не раскрытие следующей карты.
Угроза не переводится на 6: это сила отдельного нападения, а трек остаётся на 0.
Лишь завершение второй карты возобновляет прежний курсор Вестероса.

## Боты и таймеры

Боты используют те же валидаторы. Обычная/сложная политика смотрит на публичную
силу нападения и собственную власть, не читая тайные взносы или верх колоды.
Лёгкая выбирает допустимый случайный взнос. Владение троном проверяется также
для бот-решений ничьей.

Мягкий дедлайн ничего не подтверждает за человека. Жёсткий ставит 0 только
не ответившим домам, не меняя их прежние взносы. Новая ничья получает собственный
дедлайн и не истекает в том же вызове. Не реализованные последствия таймер
не разрешает и не пропускает. Серверный scheduler находит все три фазы без
подключённых браузеров.

В D.2 каждое решение по треку получает собственный дедлайн; мягкий его не
подменяет, жёсткий выбирает первый разрешённый вариант. Боты используют те же
команды: лёгкий выбирает случайный разрешённый трек, обычный/сложный — трек со
своей наихудшей текущей позицией. Расформирование использует существующие
бот-политику и жёсткий таймер Supply. Очередь, выбранный вариант и источник
вложенного Supply сохраняются в SQLite, включая промежуток между решениями.

Для Milkwater каждый сброс получает новый дедлайн. Лёгкий бот выбирает любую
разрешённую карту, обычный/сложный — карту наименьшей силы среди разрешённых.
Политика читает собственную руку и текущие варианты, а не будущую колоду одичалых.
Жёсткий таймер подтверждает первый разрешённый вариант, мягкий не меняет руку.

Для Crow Killers каждый выбор фигурки получает собственный дедлайн. Мягкий
таймер не выбирает отряды; жёсткий применяет первый разрешённый вариант.
Лёгкий бот выбирает случайный вариант, включая допустимый отказ от награды;
обычный/сложный улучшает более ценные области и предпочитает потери в менее
ценных, избегая потери последнего отряда, если есть альтернатива. Будущая колода
не участвует в решении.

В Mammoth Riders лёгкий бот выбирает случайный допустимый вариант; обычный/сложный
возвращает карту наибольшей силы и предпочитает более дешёвые потери, учитывая
область и риск потери контроля. Политика не читает будущую колоду. Мягкий дедлайн
не принимает решение, жёсткий использует первый серверный вариант.

Для The Horde Descends потери используют ту же политику, но только среди
разрешённых областей. При награде обычный/сложный бот предпочитает крепость с
двумя очками, лёгкий выбирает случайный разрешённый вариант, включая отказ.
Вложенный набор использует существующую политику Mustering. Мягкий таймер не
решает за человека; жёсткий подтверждает первый вариант, а во вложенном наборе
завершает расходование очков. Будущие карты и чужие руки в решении не участвуют.

Для Preemptive Raid лёгкий бот выбирает случайный разрешённый штраф; обычный
и сложный предпочитают потерю влияния, а при менее чем двух фигурах — потерю
имеющихся отрядов. Потери и выбор трека используют общие политики. Жёсткий
таймер выбирает первый вариант; мягкий не решает за человека. Повторное
нападение использует общие боты/таймеры взносов только для участвующих домов.

## Проверки

Go-тесты покрывают частные проекции и сырые HTTP/WS; нулевые и ошибочные взносы;
одновременное раскрытие/списание; нужную высшую/низшую группу ничьих;
повторные команды; все девять карт в обоих исходах; физическую колоду и возврат вниз;
ботов без чтения секретов; мягкий/жёсткий таймер и headless scheduler.
Отдельный SQLite-тест закрывает и открывает БД на взносах, ничьей, ожидающем
эффекте и готовом отчёте. Неизвестные ID карт и повреждённые границы проверяются
на отсутствие ложного завершения.

Тесты D.2 дополнительно проверяют оба исхода двух новых карт, границы снабжения,
отсутствие пересчёта по значкам, очерёдность низшего/остальных, возврат после
расформирования, все три варианта награды влияния, запрет Железного трона при
штрафе, сохранение использованного меча, копирование публичного выбора,
ботов всех трёх сложностей, дедлайны каждого дома и повреждённую границу.
SQLite повторно открывается на расформировании, после него, на выборе трека
и между выборами. HTTP/WS проверяют авторизацию по месту, ревизии, сохранение,
headless continuation и отсутствие внутренних очередей в проекции.

Milkwater дополнительно проверяется на полном/пустом сбросе победителя,
сохранении чужих рук, нескольких максимальных картах с младшей в руке,
обоих порядках из FAQ, освобождении руки из одной карты, подмене дома,
повторном выборе и копировании вариантов. Четыре повторных открытия SQLite
покрывают первый выбор, промежуток между сбросами, последнюю карту и уже
восстановленную руку. Реальные HTTP/WS и scheduler проверяют чужие/старые команды,
публичный выбор без внутренних списков, отдельный дедлайн и автоматическое
завершение последнего сброса без браузера.

Crow Killers проверяется на добровольных 0/1/2 улучшениях, недостатке фигур,
квоте «все»/«два», очерёдности уничтожений и замен, выборе области, контроле,
чужих и повторных командах, копировании публичных вариантов, трёх сложностях
ботов, таймерах и независимости от закрытой колоды. Семь повторных открытий
SQLite покрывают выбор потерь, промежуток между ними, замены, переход дома,
награду и досрочное завершение. Реальные HTTP/WS проверяют авторизацию,
ревизии, локализованные ошибки, публичные шаги без внутренней очереди и
headless-завершение обязательного штрафа.

Mammoth Riders покрыт тестами необязательного возврата ровно одной карты,
квот 3/2 и малых армий, четырёх типов отрядов, двух сценариев очистки портов,
сохранения контроля, копирования структурированных вариантов, ботов и таймеров.
Семь повторных открытий SQLite проверяют потери, опустевшую землю с ещё живым
портом, последнюю жертву, переход дома, ожидающую/завершённую/отклонённую награду.
HTTP/WS проверяют публичные варианты без внутренних очередей, подмену дома,
недопустимую цель, старую ревизию и headless-продолжение.

Preemptive Raid проверяется на выборе обоих штрафов, частичном выполнении,
квоте двух отрядов, портах, верхнем/нижнем положении на треках, делегировании
Трону и сохранении использованного меча. Матрица восьми следующих карт в обоих
исходах проверяет отсутствие прямых наград/штрафов исключённому дому. Проверяются
также право исключённого Трона разрешать ничьи, срок исключения, чистые взносы,
скрытие новой карты, боты и таймеры. Одиннадцать повторных открытий SQLite
покрывают штрафы и обе атаки. HTTP/WS проверяют делегированное решение, запрет
взноса исключённому дому, секретность нового взноса и конфликт старой ревизии.

## Следующий срез

Серверные последствия D.2 и интерфейс готовы для всех девяти карт. Полный маршрут
C → D → планирование включён в обычную партию. UI использует только публичные
проекции и серверные options: подтверждаемый взнос, выбор Трона, карты дома,
структурированные потери, улучшения/замены, треки, замок для набора и отказ от
необязательной награды. Решение чужого дома доступно только для просмотра.
При повторном нападении показаны освобождение дома и публичный результат первого
нападения, но не следующая карта. Локализация — `web/src/events/ru.json` / `en.json`.
История показывает последний результат и последние 40 событий из публичной модели.
