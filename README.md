# Вестерос · браузерный игровой стол

Локальная адаптация «Игры престолов: настольная игра, второе издание».
**Сейчас это сквозной тактический прототип, не полная реализация оригинальных правил.**
Работают планирование, набеги, походы, базовые бои с тайным выбором карт, отступление,
сбор власти, новые раунды и окончание партии. Боты играют эти фазы на трёх сложностях.
Со второго раунда автоматически работают три колоды Вестероса, торги за влияние
и все девять карт одичалых. Кнопка «События и Ночной дозор» открывает реальные
взносы, ничьи и последствия; «История событий» возвращает к раскрытым картам.
Работают текстовые способности 42 базовых карт в рамках текущего боевого движка.
«Битва королей» запускает тайные торги за три трека с разрешением ничьих
владельцем Трона. Часть общих боевых правил и дополнения
ещё остаются в плане.
Покрытие: [PLAN.md](PLAN.md), [контракт торгов](docs/rules/influence.md).

Особый сбор власти в замке теперь предлагает реальный выбор: получить власть или
собрать войска только в этой области. Набор проверяет снабжение, запас фигурок,
очки замка и допустимые места для кораблей. Пересчёт снабжения и общий сбор войск
работают через соответствующие события колод Вестероса.
Подробности: [снабжение и войска](docs/rules/provision.md).

## Расстановки и гарнизоны

До старта выберите **3–6 играющих домов** (люди и боты вместе).
Игра покажет только доступные для этой расстановки дома, армии и треки;
поле лобби соответствует будущей партии. Вариант на три дома подходит и для
одного человека с двумя ботами. Уменьшение числа домов не может исключить
уже подключённого человека: сначала ему нужно выбрать разрешённый дом.

На поле видны гарнизоны домов, нейтральные силы и непреодолимые области;
их правила объясняются справа. Гарнизон добавляет защиту даже без отрядов,
нейтральную силу нужно сравнять без карт и Меча, а в закрытую область войти нельзя.
Побеждённые жетоны не восстанавливаются при возврате контроля или перезагрузке.
Звёзды Королевского двора учитывают накладку на 3–4 дома и текущие позиции.

В обычном бою **без перевеса Меч тоже работает**: после раскрытия карт его
владелец выбирает +1 либо сохранение на следующий бой. Расход общий с заменой
перевеса, только раз за раунд; таймеры и восстановление решения работают так же.
Подробнее: [расстановки, гарнизоны и Меч](docs/rules/setup-and-blade.md).

## Языки: RU / EN

Кнопка **RU / EN** в верхней панели переключает интерфейс, обучение, названия
областей и приказов, описания 42 базовых карт, ошибки и хронику партии.
Язык сохраняется в браузере; участники одной комнаты могут выбрать разные языки.
Перезагрузка партии не требуется, состояние и таймер не сбрасываются.
Для первого открытия на английском: <http://localhost:18081/?lang=en>.
Имена игроков и названия созданных комнат не переводятся. Текст, уже нарисованный
в оригинальных изображениях, остаётся исходным; подписи и описания поверх карт переводятся.
Словари: [UI](web/src/locales/README.md), [карты и сервер](internal/game/locales/README.md).

## Запуск в Docker

Образы публикуются в `ghcr.io/maintainer64/thrones` для Linux amd64/arm64:

| Событие | Теги образа | Тесты |
| --- | --- | --- |
| PR №N из ветки этого репозитория | `dev-N` | Полный CI |
| Публикация стабильного релиза `v1.2.3` | `1.2.3`, `v1.2.3`, `latest` | Не запускаются |
| Публикация prerelease `v1.3.0-rc.1` | `1.3.0-rc.1`, `v1.3.0-rc.1` | Не запускаются |
| Обычный push, включая push Git-тега | Не собирается | Не запускаются |

Для выпуска образа создайте и опубликуйте GitHub Release с SemVer-тегом
(`v1.2.3` или `1.2.3`). Сам push тега и сохранение черновика релиза
публикацию не запускают. `latest` обновляется только стабильным релизом.
У PR из внешних форков работают проверки; публикация требует PR из ветки
этого репозитория, поскольку используется его `GITHUB_TOKEN`.

Локальная сборка:

```bash
docker compose up --build -d
```

Открыть <http://localhost:18081>. Создать комнату, перед приглашением друзей заменить нужных
ботов на игроков и скопировать ссылку. Проверять второго игрока в другом браузере или приватном окне.
Ведущий по умолчанию играет Старком. До старта должны быть заняты все человеческие места.
Назначьте приказы отрядам, подтвердите готовность и после общего раскрытия нажмите «К действиям».
В походе выберите область с приказом, количество отрядов и цель на поле. Приказы можно пропускать.

## Вестерос и Ночной дозор

После завершения действий первого раунда сервер открывает три карты Вестероса.
События разрешаются по порядку I → II → III; снабжение, набор и торги используют
свои окна. Решения владельцев жетонов и последствия одичалых находятся в окне
событий. Чужие взносы и следующая карта одичалых скрыты до раскрытия.
Взнос, выбор отряда, карты дома и трека требуют подтверждения. Закрыть окно
можно без пропуска решения; повторное открытие и перезагрузка сохраняют ход.
Сервер продолжает автоматические шаги без вкладки; мягкий таймер не решает за игрока.
Открытая карточка не заменяется окном следующего решения из-за действий ботов:
пока вы читаете, остаётся один снимок события. При переходе партии дальше внизу
появляется «Продолжить»; устаревшие действия отключены. Это не останавливает
общий сервер и остальных игроков. Приказы и решения вашего текущего этапа
по-прежнему обновляются через WebSocket.
Возврат в фоновую вкладку один раз актуализирует снимок комнаты; далее обновления
приходят через WebSocket, без постоянного опроса сервера.

Словари модуля: `web/src/events/ru.json` и `en.json` с одинаковыми стабильными
ключами. Художественные карточки необязательны для правил; импорт локальных
материалов из соседней reference-папки:

```bash
node scripts/import-event-cards.mjs
```

Можно передать первым аргументом другую папку `public/images`, содержащую
`westeros-cards/` и `wildling-cards/`. Внешней загрузки или публикации нет:
24 изображения копируются в `local-assets/events/`, подключённый Compose read-only.
Без них остаются названия, описания и все действия.

Проверка UI на настоящем Go HTTP/WS и временной SQLite, без fixture API в продукте:

```bash
pnpm --dir web build
node scripts/sync-web.mjs
WESTEROS_BROWSER_TEST=1 SOFTWARE_WEBGL=1 go test -v ./internal/server -run '^Test(Events|Influence|Provision|Raven|SetupBlade|Panels|Combat|CombatMatrix|Tides|Artwork|Orders)Browser$' -count=1 -timeout=40m
```

Для выборочного прогона можно добавить `WESTEROS_BROWSER_GREP` с регулярным
выражением названия сценария. Например, повторить оба сценария переподключения:

```bash
WESTEROS_BROWSER_TEST=1 SOFTWARE_WEBGL=1 WESTEROS_BROWSER_GREP='private Tides choice' go test -v ./internal/server -run '^TestCombatMatrixBrowser$' -count=3 -timeout=10m
```

В CI каждый из 11 наборов запускается в отдельной matrix job (до трёх одновременно),
а не в одном процессе с общим таймаутом. Наборы используют один и тот же собранный
фронтенд, индекс изображений и WebP из артефакта `browser-build`. При падении
сохраняются `browser-failure-<Suite>`: снимки, контекст ошибки и Playwright trace.
Сценарии с внешними API-командами ждут применения серверной ревизии в React
(`data-room-revision`), а не только ответа HTTP. Проверка переподключения
закрывает только открытое соединение и ждёт новое.

Для воспроизведения задержек медленного runner:

```bash
WESTEROS_CPU_THROTTLE=4 WESTEROS_BROWSER_TEST=1 SOFTWARE_WEBGL=1 go test -v ./internal/server -run '^Test(Orders|SetupBlade|Tides|Influence|Combat)Browser$' -count=1 -timeout=20m
```

`WESTEROS_CPU_THROTTLE` (1–8) используется этими пятью наборами и замедляет
настоящий Chromium через CDP, без подмены сервера или его ответов.
Необязательные снимки успешных проверок включаются `WESTEROS_VISUAL_CHECKS=1`.
По умолчанию они отключены: GPU-readback со SwiftShader способен занимать
десятки секунд на один снимок и не является функциональной проверкой.
Все проверки приказов/карточек/3D-поля остаются включены. При ошибке сохраняются
финальный screenshot, DOM snapshots и network trace; непрерывный GPU screencast
отключён. В режиме визуальных снимков отключаются CSS-анимации и действует
отдельный лимит 15 секунд на снимок.

При `PLAYWRIGHT_MANAGED_CHROMIUM=1` используется полный Chromium в новом
headless-режиме (`channel: chromium`), как локальный Chrome. Установка
`playwright install --with-deps chromium` уже включает этот браузер.
При выключенных анимациях 3D-поле рисуется по изменениям, а не непрерывно;
zoom/fit и управление камерой остаются доступны. Анимированный повтор боя
по-прежнему использует непрерывную отрисовку.

## Посыльный ворон

После раскрытия приказов кнопка «К действиям» сначала открывает шаг Ворона.
Владелец Королевского двора может заменить один свой раскрытый приказ, тайно
посмотреть верхнюю карту одичалых либо отказаться. После просмотра доступны
только возвращение наверх или перекладывание вниз; закрытие окна ничего не отправляет.
Чужие игроки не видят карту и выбранное размещение. Шаг сохраняется при reload,
боты и жёсткий таймер выполняют его без браузера. Само 3D-поле не изменено.
Подробнее: [контракт и ограничения Ворона](docs/rules/raven.md).

## Показ нападения и история боёв

Перед выбором карты открывается окно с маршрутом, составом и силой обеих сторон:
видны число фигурок, сила за одну, приказы, своя поддержка и гарнизон.
После боя — итоговый разбор, карты, эффекты, потери и отступление. Числа считает
Go, React только отображает строки; скрытые карты заранее не раскрываются.

Бои не исчезают за следующим раундом: непрочитанные окна идут последовательно,
последний результат показывается до Вестероса. Свое обязательное решение можно
открыть сразу. В панели домов доступна история последних 40 боёв; «Показать бой
на поле» открывает историческую 3D-сцену, не изменяя живую партию. Отправленные
отряды движутся к цели; карты раскрываются явно, сила складывается по серверным
слагаемым, затем показываются сохранённые потери и известное отступление.
Есть пауза, пропуск и статический режим с учётом reduced-motion.
Конечная расстановка сохраняется сервером отдельно: повтор корректно показывает
возврат от Арианны, улучшение Ренли, уничтожение без отступления и победу без
выжившей армии после черепа перевеса.
Режиссируемая анимация движения и потерь остаётся следующим визуальным шагом.
Подробнее: [контракт показа боя](docs/rules/combat-presentation.md).

## Панель действий на поле

Поход и набег выполняются в одной правой панели, без второй формы под картой.
Выберите состав похода, затем допустимую цель на поле или в списке и подтвердите.
«Показать цели» наводит камеру; Escape отменяет выбор, а «Снять приказ без действия»
позволяет продолжить даже при отсутствии целей. Закрытую панель можно вернуть
кнопкой «Открыть панель действий» под полем.

Во время планирования показаны власть и оставшиеся звёзды: особые приказы
не расходуют власть. Уже выданные жетоны остаются в палитре затемнёнными.
Описание имеет постоянную высоту и не сдвигает приказы при наведении.
При сборе войск видны три шага, оставшиеся очки выбранного замка, текущие фигурки
и стоимость набора/улучшения. Нажатие допустимого варианта сразу расходует очки;
потеря оставшихся очков по завершении требует подтверждения.

## Карты перевеса (Tides of Battle)

При создании комнаты включите «Карты перевеса». До старта ведущий может
изменить режим через настройки; после старта он зафиксирован. По умолчанию выключен.

Полная колода состоит из 24 карт, но изображений всего шесть:

| Тип | Копий | Сила | Дополнительный знак |
| --- | ---: | ---: | --- |
| `zero` | 8 | +0 | — |
| `sword` | 4 | +1 | 1 меч |
| `fortification` | 4 | +1 | 1 крепость |
| `two` | 4 | +2 | — |
| `three` | 2 | +3 | — |
| `skull` | 2 | +0 | 1 череп |

Перед каждым боем колода перемешивается заново. После карт Домов обе стороны
берут по карте без возвращения в колоду. Владельцу неиспользованного Валирийского
меча предлагается сначала заменить свою скрытую карту, либо после раскрытия
обеих карт добавить +1 к силе. Применить меч можно только один раз за раунд;
новый раунд восстанавливает жетон, смена владельца в текущем раунде — нет.
Скрытые карты и остаток колоды сохраняются в SQLite, но чужому игроку не выдаются.
Перезагрузка страницы не даёт повторного выбора или новой карты.

Мечи и крепости добавляются к боевым знакам карты Дома. Череп применяется после
обычных потерь независимо от победителя, игнорирует крепости, но учитывает
защиту Чёрной Рыбы. Гарнизон не является отрядом и от черепа не погибает.
Боты и жёсткий таймер умеют завершать оба шага выбора меча. Результат боя
показывает обе карты, итоговую силу и способ применения меча. Назначение потерь
остаётся автоматическим, как и в остальном текущем прототипе.

Правила: [базовая книга, стр. 29](https://images-cdn.fantasyflightgames.com/filer_public/30/4f/304f72e3-4fe4-4f91-bfbe-75133161b092/va65_agot2_rulebook_web.pdf),
[FAQ 2.0, стр. 1](https://images-cdn.fantasyflightgames.com/filer_public/cf/06/cf06eb26-48e3-46b9-b57c-f053beb2518d/agotbg_faq_v2_forweb.pdf).
Изображения локальны: [описание ассетов](local-assets/tides-of-battle/README.md).
Типы карт и решений вынесены в именованные Go-типы/константы и
`web/src/enums.ts`; тест проверяет совпадение значений протокола.
Карту можно перетаскивать и масштабировать колесом; кнопка прицела показывает поле целиком.
Звуки включаются отдельно; анимации можно отключить. Кнопка академической шапочки открывает обучение.

По умолчанию на решение даётся **5 минут, мягкий лимит**: после нуля ход не прерывается.
Ведущий может изменить длительность (1–120 минут) и включить жёсткий режим только до старта.
Жёсткий режим работает на сервере и без открытых вкладок: пропускает приказ, завершает
планирование с недостающими приказами или выбирает безопасный вариант карты/отступления.
Дедлайн хранится в SQLite и не сбрасывается при перезагрузке страницы или контейнера.

## Ассеты и исходники

Подготовленные `local-assets/` можно хранить в обычном Git: они больше не исключены
из индекса. Это не означает их
автоматическую публикацию или изменение прав на оригинальное оформление.
Редактируемые исходники вынесены из проекта в `../westeros-web-references/asset-sources/`.
Исходник рамок карт сохранён там в `cards/исходники/`; резервные PSD/CDR и
92 неиспользуемых импорта вынесены рядом в `../westeros-web-workbench/` без удаления.
В папке резерва сохранён manifest с контрольными суммами для восстановления.
Полный сырой экспорт Unity остаётся в `~/Desktop/Resources.out`, как был.
В образ не включаются ни исходники, ни runtime-ассеты — Compose подключает
`local-assets` отдельным read-only volume.
Подробнее: [исходники](../westeros-web-references/asset-sources/README.md).
При намеренной пересборке рамок `node scripts/import-card-art.mjs` использует
новый путь по умолчанию; при необходимости передайте другую папку первым аргументом.

```bash
uv run --with UnityPy python scripts/import-installed-game.py
docker compose up --build -d
```

Скрипт читает `/Applications/A Game of Thrones The Board Game.app`, не изменяя приложение.
В `local-assets/` попадают базовые карточки и выбранные текстуры эффектов; папка исключена из Docker build context.
Compose подключает её read-only, а сервер отдаёт файлы отдельно от встроенного фронтенда.
При отсутствии локальных ассетов используются изображения референсного проекта.
Unity-аудио экспортируется только при поддержке формата; иначе используются браузерные OGG-звуки.
Оригинальные Unity-сцены обучения не исполняются: сделан собственный русский тур по рабочему интерфейсу.
Сама установленная игра не содержит русского перевода карточек — текст на оригинальных картах остаётся английским.

### Карты домов крупным планом

Карты в руке, выборе боя и его результате используют один компонент. Нажмите карту
в руке: откроется увеличенный просмотр с масштабом 80–200%, переключением ← / → и
закрытием по Esc. Внутри увеличенной карты работают лёгкое движение портрета,
наклон вслед за мышью, блик и частицы; это **не видео и не скелетная анимация персонажа**.
Общая кнопка «Анимации» и системный `prefers-reduced-motion` отключают эффекты.

Русские имена и краткие описания всех базовых карт лежат отдельно:
`internal/game/locales/ru.json`. Их отдаёт API; названия на самой карте, в руке,
просмотре и окне боя не зависят от английских имён файлов текстур.
В просмотре показана способность. Бой включает отдельные сохраняемые решения
Тириона, Эйрона, Дорана, Королевы Шипов, Ренли, Серсеи, Робба и Пестряка.
Для Робба выбор чужого отступления по-прежнему выполняется на карте.
В отчёте боя раскрывается список эффектов. Боты и жёсткий таймер умеют завершать
эти шаги. Взаимодействия сверены с [FAQ 2.0 издателя](https://images-cdn.fantasyflightgames.com/filer_public/cf/06/cf06eb26-48e3-46b9-b57c-f053beb2518d/agotbg_faq_v2_forweb.pdf).
Это не завершение всех оригинальных правил: пока остаются ограничения поддержки
только своим домом, автоматического выбора потерь и отсутствия раненых.
Пока разрешены направления отступления, вмещающие всех выживших; частичное
сокращение армии из-за снабжения отдельно не моделируется. Описания карт не
означают, что эти отсутствующие общие механики уже появились.

HD-иллюстрации персонажей, лидеров домов, событий и перевеса читаются прямо из
`local-assets/`. Оригинальные PNG не изменяются: сборка создаёт рядом актуальные
WebP-копии в полном разрешении (RGB quality 92, alpha quality 100), без обрезки
или уменьшения размеров. Старые низкоразрешённые WebP из `cards/` не подменяют
новые иллюстрации. Имена, сила, символы и локализованные способности
остаются отдельными игровыми элементами поверх иллюстраций.

Приказы используют **пять** исходных PNG в `web/public/media/orders/`:
`March`, `Defend`, `Support`, `Raid`, `Consolidate`. Звезда особого приказа и
его числовой модификатор рисуются компонентом `OrderToken` по данным Go-каталога,
включая одновременные ★ и `+1`/`+2`. Нулевой поход явно показывает `0`;
сбор власти, набег и обычная поддержка не получают выдуманного боевого бонуса.
Один компонент применяется в панели приказов, окне Ворона, просмотре выбранного
приказа и поверх 3D-поля. Картинки `MarchP`/`MarchM` и другие варианты больше не нужны.
В веб-сборку входят только WebP-копии пяти баз, без тяжёлых PNG-исходников.
Все производные имеют SHA-256-версию в URL; локальные портреты
по-прежнему подключаются read-only. Меч и башня на картах — отдельные масштабируемые
SVG-символы с металлической фактурой, а не одинаковые щиты.

```bash
pnpm --dir web artwork:index
pnpm --dir web build
docker compose up --build -d
```

Индекс `web/src/artwork/index.json` хранит путь WebP-копии, исходные размеры,
контрольные суммы PNG/WebP и их размер в байтах. Версия WebP добавляется в URL,
поэтому после замены PNG браузер получает новую картинку, а не старую из кеша.
`artwork:index` конвертирует только изменённые PNG; кеш проверяет исходник,
параметры кодировщика и целостность результата. PNG не перезаписываются.
Локальная сборка запускает этот шаг автоматически; Docker и CI без папки
локальных ассетов сохраняют её индекс, но подготавливают пять встроенных приказов.
После замены файлов сначала выполните `artwork:index`, затем пересоберите образ.
Локальные PNG и WebP подключаются существующим read-only volume и не включаются
в Docker-образ. Для переноса ассетов нужны WebP-копии рядом с исходниками.

Текущие 78 изображений: **207,6 МиБ PNG → 34,8 МиБ WebP (−83,2%)**.
Мечи, башни и звёзды остаются SVG. Проверки конвертера покрывают сохранение
размеров/прозрачности, неизменность PNG, кеш и восстановление повреждённых копий.

Старая коллекция `web/public/media/cards/` не нужна: интерфейс использует
индекс HD-портретов, без запасных PNG-карточек и без загрузки старого manifest.
56 прежних карт и неиспользуемый `T_crd_none_blank.png` сохранены вне проекта
в `../westeros-web-workbench/unused-cards-2026-10-23/` (18,3 МиБ).
Там лежит `archive-manifest.json` с исходными путями, SHA-256 и прежними ссылками
для восстановления. Скрипт `node scripts/archive-unused-cards.mjs` показывает
план без изменений; `--apply` перемещает только эти устаревшие PNG и отказывается
трогать исходники, зарегистрированные WebP-конвертером. Все 78 актуальных PNG
сохранены, как и используемые PNG отрядов и текстуры 3D-поля. Повторный экспорт
игровых данных больше не создаёт старую папку карточек.

`scripts/import-card-art.mjs` — старый импорт 512×512 Unity-атласов и рамок PSD;
для новых HD PNG он не нужен. PDF с текстами альтернативных колод не подменяют
базовые правила, состав карт или пока не реализованные способности.

## Игровой 3D-режим

До начала партии каждый игрок выбирает свободный дом: при создании комнаты,
по ссылке-приглашению или в панели своего дома в лобби. Можно занять место бота;
другого игрока заменить нельзя. В одиночной партии остальные пять домов ведут боты.
Выбор сохраняется при перезагрузке страницы и блокируется после старта партии.

Интерфейс оформлен общими материалами пергамента, кожи и бронзы; игровое поле
и управление камерой остаются 3D. Кнопка «Влияние» открывает три вертикальные
дорожки с фактическими местами домов и заменяет инспектор области, не перекрывая поле.
Щит силы из локального экспорта можно повторно импортировать командой
`node scripts/import-ui-assets.mjs [папка Texture2D]`; при его отсутствии работает CSS-оформление.
Экран боя использует реальные результаты сервера, а не демонстрационные значения.
Верхней служебной шапки нет: язык, звук, анимации, обучение, правила и настройки
комнаты открываются через шестерёнку. Таймер находится рядом с текущей фазой,
ресурсы дома — в его панели. Меню закрывается по Escape или нажатию вне него.
На стартовом экране прокручивается только форма, описание остаётся на месте.
Карты при масштабе 100% вписываются по обеим сторонам доступной области;
увеличенный просмотр прокручивается отдельно. Alegreya с кириллицей поставляется
локально через Fontsource, без обращений к внешнему сервису шрифтов.
Лицензия шрифта: `web/public/fonts/OFL-Alegreya.txt`.

На <http://localhost:18081> создайте или откройте комнату: сразу откроется 3D-стол.
Это представление настоящей партии: армии, приказы, выбор области и действия
работают через Go-сервер и WebSocket. 2D-рендерер и переключатель режимов удалены.

Игровой HUD выделяет поле: панели «Дома» и «Область» можно скрывать, а рука дома
расположена отдельной колодой внизу. Рука также сворачивается — камера подстраивает
поле под освободившееся место. Карты упорядочены по силе; просмотр листает их в том
же порядке. Сброшенные карты отмечены отдельно, действия выполняет прежний Go-движок.

`availableOrders` в персональном снимке комнаты содержит только доступные жетоны
для каждой своей области. Список строит тот же немутирующий валидатор, который
проверяет команду: учитываются фаза, готовность, принадлежность армии, использованные
жетоны и лимит звёзд. Сбор власти в прототипе разрешён только на суше, поскольку
морские/портовые правила сбора пока не реализованы. Чужие скрытые приказы для этого
не запрашиваются. Выбранный приказ можно снять до подтверждения готовности.

Камера держит наклон 45°: левая кнопка и перетаскивание сдвигают стол,
правая поворачивает его, колесо приближает к курсору. Кнопки +/− меняют масштаб,
«Стол» восстанавливает общий вид, «Область» приближает выбранную территорию.
Границы можно отключить; выбранная область и допустимые цели выделяются отдельно.
В свой ход выберите отряд → подсвеченную цель → **«Подтвердить поход»** под картой.
Количество войск на этой панели синхронизировано с правой колонкой. Esc отменяет
выбор; нажатие на цель ещё не отправляет отряды. Go проверяет цели в read-only
`POST /api/rooms/{room}/preview` тем же валидатором, что исполняет команды,
включая снабжение, выбранные отряды, гарнизоны и транспорт флотом.

Набег без допустимых целей можно завершить кнопкой «Снять приказ без действия»
прямо под картой, в том числе при ошибке загрузки предпросмотра.
При отступлении поле остаётся доступным: сервер подсвечивает разрешённые области,
нажатие выбирает цель, а «Подтвердить отступление» перемещает выживших. После
перезагрузки вкладки выбор доступен снова; чужое отступление не блокирует карту.
Драконий Камень получил отдельную стилизованную каменную поверхность по исходному
контуру острова; порты размещаются внутри своей морской области ближе к берегу.
Это визуальное оформление, не изменение типов территорий или правил соседства.

Поле теперь имеет настоящую геометрию рельефа: приподнятую сушу, побережье и горы.
Это **стилизованная авторская карта высот**, а не извлечённый оригинальный terrain.
Она привязана к исходным контурам суши и географическим ориентирам; море остаётся
плоским, порты вырезаются из суши. Геометрия, фигурки, подсветка и маршруты используют
одну карту высот. Исходные файлы установленной игры и экспорты не изменяются.

Импорт готовит модели пехоты, конницы, кораблей и осадных орудий с текстурами
шести домов. У пехоты и конницы восстановлены исходные Idle/Run, у кораблей —
движение парусов; осадное орудие пока без анимации атаки. Перемещения фигурок
следуют подтверждённым сервером походам, а не меняют правила на клиенте.
Контуры всех 58 территорий берутся из исходных MeshCollider, включая составные
морские области. Доступен выбор кликом по самой карте, фигуре или подписи.
Для увеличения выбранной области нажмите «Область»; «Стол» возвращает общий вид.
Подписи появляются при приближении и наведении. Скрытые приказы соперников
не запрашиваются отдельно: сцена использует только персональный снимок комнаты.

Если 3D-ассетов нет, показывается инструкция импорта и кнопка повторной загрузки.
Для игры нужен WebGL 2; при ошибке комната остаётся сохранённой. Прежние ограничения правил прототипа остаются:
новый рендерер сам по себе не добавляет Вестерос, способности карт и дополнения.

На планшете касание выбирает область, один палец сдвигает поле, два пальца меняют
масштаб и поворачивают стол. Перетаскивание и мультитач не выбирают цель по отпусканию.
Поход по-прежнему выполняется только отдельной кнопкой подтверждения.
Жетоны приказов имеют подписи и постоянную область объяснения: наведение, фокус
или касание показывают действие приказа и ограничения текущего прототипа.
Карты в руке подсвечиваются без увеличения поверх соседей. Отдельная диагностическая
«3D-проба» удалена: всё взаимодействие происходит в настоящей игровой комнате.

### Подготовка 3D-ассетов

Полный импорт также подготавливает исходные модели Castle, Stronghold и Port.
Сцена размещает 20 замков/крепостей по `castleLevel` и 8 портов по типу области,
с привязкой к карте высот и проверкой точки внутри исходного контура.
Это архитектурные обозначения, а не дополнительные войска или новые правила.
Чтобы добавить их к уже подготовленным локальным ассетам без полного переимпорта:

```bash
node scripts/import-landmarks.mjs "$HOME/Desktop/Resources.out/AssetRipper_export_20261018_045740/Assets"
```

Исходные файлы читаются без изменений. Как и прочие ассеты установленной игры,
эти модели находятся в `local-assets/`, доступны для локального Git и не включаются в Docker-образ.

Подготовка из двух локальных экспортов AssetRipper (Unity YAML и GLB):

```bash
pnpm --dir web install --frozen-lockfile
node scripts/import-3d-assets.mjs "$HOME/Desktop/Resources.out"
docker compose up --build -d
```

Импорт читает исходники, восстанавливает skin/bind poses и переносит кривые анимации
в glTF. Вырезает две плоскости карты из большой сцены и сжимает их текстуры без
изменения разрешения. Результат — около 5,1 МБ для поля и 604 КБ для фигурки с клипами.
Blender и Unity для запуска не требуются. Подготовленные файлы лежат в
`local-assets/preview3d/`, не коммитятся и не включаются в Docker-образ:
Compose подключает их read-only. Для браузера нужен WebGL 2.
Если экспортов нет, приложение показывает инструкцию импорта вместо поля.
Этот же импорт готовит `game-manifest.json`, контуры территорий и модели для
игрового режима. Все подготовленные 3D-материалы вместе занимают около 17 МБ;
в Git и Docker-образ они не попадают.

```bash
docker compose logs -f app
docker compose down
```

SQLite хранится в volume `game-data` и переживает перезапуск. Не добавлять `down -v`,
если нужно сохранить комнаты. Место игрока восстанавливается по cookie этого браузера;
одна ссылка комнаты не даёт доступа к чужому месту. При удалении cookie восстановление пока невозможно.
По умолчанию порт открыт только на компьютере, не на всю локальную сеть.

## Разработка

Нужны Go 1.26.2+, Node 24+ (только для сборки интерфейса) и pnpm 11.13.0.
Версия pnpm закреплена в `web/package.json`; зависимости — в `web/pnpm-lock.yaml`.

```bash
make build
./bin/westeros
```

Горячая разработка: после первой сборки запустить Go-сервер и отдельно `cd web && pnpm dev`.
Интерфейс доступен на порту 5174; Vite проксирует API, WebSocket и карту в Go на 18081.
Для отдельного локального Go-сервера можно указать
`VITE_BACKEND_TARGET=http://127.0.0.1:18082 pnpm dev` из `web/`.

```bash
make test
cd web && pnpm build
```

Проверка запущенного контейнера, двух игроков и сохранения после перезапуска:

```bash
node scripts/smoke.mjs --restart
```

Команда создаёт отдельную тестовую комнату и перезапускает только сервис `app` этого Compose.

Проверки браузера (используют уже установленный Chrome, без скачивания браузера):

```bash
cd web
pnpm test:e2e
```

Можно указать `BASE_URL` и `CHROME_EXECUTABLE_PATH`. Тесты создают отдельные комнаты.
Игровые E2E требуют локально подготовленных ассетов; без них доступны сценарии
`pnpm exec playwright test game.spec.ts -g 'missing 3D|mobile'`. Для headless-проверки WebGL на этой
машине можно задать `SOFTWARE_WEBGL=1` (программный рендеринг Chromium).
Чистые тесты импорта без художественных материалов: `node --test scripts/lib/*.test.mjs`.

`LISTEN_ADDR` (по умолчанию `127.0.0.1:18081`), `DATA_DIR` (по умолчанию `.local-data`),
`COOKIE_SECURE=true` — для HTTPS за доверенным reverse proxy. Для локального HTTP оставить false.
`LOCAL_ASSETS_DIR` — путь к локально импортированным материалам; в Compose задан автоматически.
Это один экземпляр сервера; горизонтальное масштабирование и публичный хостинг пока не предусмотрены.

## Архитектура

```text
React → HTTP-команды с ревизией → Go: валидация и правила → SQLite
React ← персональные снимки по WebSocket ← Go
```

- `internal/game` — правила прототипа, персональные представления, таймеры и стратегии ботов.
- `internal/server` — комнаты, cookie-идентичность, HTTP и WebSocket.
- `internal/store` — SQLite, атомарная проверка ревизии.
- `web` — React, TypeScript и карта.
- `internal/assets` — фронтенд, встроенный в Go-бинарник при сборке.

Никакого Goja или JS-движка в сервере. В контейнере нет Node, pnpm, Python, Postgres и Redis.
Команды отправляются по HTTP, а WebSocket доставляет обновления состояния.
Чужие приказы не просто скрыты интерфейсом: они не попадают в персональный ответ сервера.
Боты планируют приказы, выполняют набеги и походы, выбирают боевые карты и отступления.
Лёгкий уровень случайный; обычный предпочитает ценные области; сложный дополнительно оценивает
видимую оборону и сохраняет гарнизоны. Это эвристики, не поисковый AI и не доказательство полного знания правил.
Решения ботов исполняются по одному серверным тиком, сохраняются и передаются по WebSocket:
они продолжают играть без открытых вкладок, а на поле видны отдельные ходы, не мгновенная пачка перемещений.

## Правила и происхождение

Официальные PDF перечислены в [каталоге](docs/rules/catalog.json). Скачать локальную коллекцию:

```bash
node --use-env-proxy scripts/download-rules.mjs
```

Копии и контрольные суммы сохраняются в `local-rulebooks/`, не включаются в Git или образ.
Если сайт издателя недоступен, скрипт сообщает об ошибках; каталог ссылок остаётся доступен.

Данные поля и исходных армий взяты из [Swords and Ravens](https://github.com/Longwelwind/swords-and-ravens).
Старые проекты `agot-bg-*`, Compose, build/deploy-скрипты и документация сохранены
отдельно в соседней папке `../westeros-web-references/` ([описание](../westeros-web-references/README.md)).
Они не входят в основное дерево проекта и не нужны для сборки или запуска:
подготовленные данные уже находятся в `internal/game/catalog.json` и `web/public/media/`.
Только для намеренного повторного экспорта используется:

```bash
node scripts/export-game-data.mjs
# Другой источник или проверка без перезаписи проекта:
node scripts/export-game-data.mjs --source ../westeros-web-references/agot-bg-game-server --output /tmp/westeros-export
```

Источник можно также задать через `WESTEROS_REFERENCE_DIR`. Обычный запуск
экспорта перезаписывает подготовленные файлы; `--output` позволяет проверить результат отдельно.
